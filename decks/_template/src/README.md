# Deck Template (sli.dev)

A starter for [sli.dev](https://sli.dev) presentations published under `inturious.com/decks/<slug>/`.

A "deck" here is just a folder with a `slides.md` (and optional `public/` for static assets). Slidev itself is installed once at the project root and shared across all decks — no per-deck `package.json` or `node_modules`.

This folder (`decks/_template/`) is the template itself and is NOT deployed (the build script skips any folder starting with `_`).

## Creating a New Deck

1. Make the folder and copy the starter slides:
   ```bash
   mkdir -p decks/<deck-slug>/src
   cp decks/_template/src/slides.md decks/<deck-slug>/src/slides.md
   ```

2. Edit `decks/<deck-slug>/src/slides.md` — update the title, frontmatter, and content.

3. Add any images to `decks/<deck-slug>/src/public/img/` — slidev serves them at the deck root.

4. Preview locally (from project root):
   ```bash
   pnpm install                                              # first time only
   pnpm slidev decks/<deck-slug>/src/slides.md               # http://localhost:3030
   ```

5. Commit. Vercel builds and deploys to `https://inturious.com/decks/<deck-slug>/`.

6. When publishing publicly, add an entry to the "Talks & Decks" list in the root `index.html` (above the Portfolio section). Format: title link + `<span class="talks-meta">YYYY-MM-DD · City</span>`. The sitemap auto-discovers the new deck — no extra step.

## Draft Mode

Prefix the deck folder with an underscore (e.g. `decks/_my-draft/`) to keep it out of production:

- `scripts/build-decks.sh` skips any `decks/_*` folder, so no public URL is generated.
- `.vercelignore` excludes `decks/_*/` from the Vercel upload, so even stray built files won't ship.
- `pnpm slidev decks/_my-draft/src/slides.md` still works locally.

Drop the underscore when you're ready to publish.

## Layout

```
decks/<deck-slug>/
├── src/
│   ├── slides.md       # the presentation
│   └── public/         # static assets — served at deck root
└── (built output)      # index.html, assets/ — generated by Vercel build, gitignored
```

## Slidev Version

`@slidev/cli` and `@slidev/theme-default` are pinned in the root `package.json`. Upgrade once, all decks pick it up.

## When You Need Per-Deck Dependencies

If a deck needs a non-default theme or an addon (e.g. `@slidev/theme-seriph`), add it to the root `package.json` rather than recreating per-deck config. All decks share the same slidev install — that's the point.

If a deck needs *truly isolated* dependencies that would conflict with others, that's a sign the deck-as-folder model has stopped fitting. At that point, consider giving that one deck its own `package.json` and `pnpm-workspace.yaml` entry as a one-off exception.
